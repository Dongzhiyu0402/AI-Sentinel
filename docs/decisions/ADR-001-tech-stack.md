# ADR-001：MVP 技术选型

## Status
Accepted（2026-10-26）

## Background
5 天内要交付可公网访问的内容合规检测工具，团队 3 人（1 人主技术、1 人主规则、1 人主前端与数据），已有阿里云轻量服务器。核心风险是时间与环境不确定性：不能把工期耗在构建链路、C 扩展编译或框架学习上。

## Decision
1. 后端 FastAPI（Python），与团队技术栈一致；
2. 规则匹配使用自实现纯 Python Aho-Corasick，不依赖 pyahocorasick（避免 Windows 编译失败）；
3. 规则库放 YAML，与代码解耦，运营可独立维护、Git 版本管理；
4. 前端使用原生 HTML/CSS/JS 单页，无构建步骤，FastAPI 直接托管静态文件；
5. LLM 只做"高风险改稿建议"，未配置密钥或超时自动降级为模板建议；
6. 暂不落库原文，只记录脱敏统计（满足隐私承诺）。

## Consequences
- 正面：零编译依赖、一条命令启动、迭代快；规则改动无需发版；演示环境稳定。
- 负面：前端无框架，页面复杂度上升后需要重构（11 月评估 Vue/React）；规则量到 500+ 时需要索引与缓存优化（届时评估内存与启动时间）。
- 后续：若规则库扩到 500 条以上，评估将"规则热加载"与"规则版本灰度"纳入迭代。
