# 交付规范（团队级 P0）

> 适用：合规哨兵全部代码、界面、文档、官网、演示视频与参赛材料。
> 原则：**成品必须达到可对外交付的生产级标准：真实文案、统一图标、可维护代码、可验证数据。**
> 违反任一条 → 门禁不通过，退回重做。

## 1. 绝对禁止（出现即退回）

| 类别 | 禁止内容 | 说明 |
|---|---|---|
| 图标 | emoji 作为功能图标 | 统一使用锁定的一套 SVG 图标库，尺寸 16/20/24px |
| 视觉 | 紫色→粉色渐变、发光边框、毛玻璃三件套 | 主色不超过 3 个，允许纯色 Indigo/Slate Blue |
| 文案 | Lorem ipsum、Welcome to、Sign up today、"示例项目""Demo 项目" | 所有文案必须具体、可执行 |
| 占位与未完成标记 | "TODO""FIXME""占位符""示例项目""Demo 项目" | 用户可见处与代码注释中一律不得出现 |
| 代码 | console.log 调试残留、无用注释、复制粘贴的重复块 | 提交前自检 |
| 数据 | 编造的测试数据、虚构用户、虚假合作方 | 验证数据必须可复现、可追溯 |

## 2. 文案规范

- 只写真实能力：不承诺"检测 AI 生成"，不承诺"保证通过审核"。
- 风险提示必须可行动：每条命中给出"依据 + 建议"，不只标红。
- 错误信息写"发生了什么 + 怎么办"，不写"系统错误"。
- 空态不写"暂无数据"，写"当前没有需要处理的风险，建议发布前人工复核"。

## 3. 代码规范

- 分层：routes → services → schemas/core；入口文件只装配，零业务。
- 单文件 ≤300 行；函数单一职责；命名用业务语言（rule_engine / check / finding），不用 a/b/tmp。
- 所有颜色走 Token（CSS 变量），组件内不硬编码色值（`#fff` `#000` 除外）。
- 网络请求必须有超时、错误分支与降级路径。
- 不提交密钥；配置走环境变量；样例配置用 `.env.example`（不含真实值）。

## 4. 发布前清理清单（每次交付执行）

> 扫描范围：`frontend/**`、`README.md`、对外材料。内部设计/架构文档中的排版符号（√ / × 等）不视为 UI 图标，不参与 emoji 门禁。

```bash
# 1) 占位与未完成标记
grep -RInE "TODO|FIXME|Lorem|占位|示例项目" \
  backend frontend docs README.md --exclude-dir=__pycache__

# 2) emoji 扫描（图标禁用）
grep -RInP "[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}]" frontend docs README.md

# 3) 调试残留
grep -RInE "console\.(log|debug)|print\(" backend frontend --include="*.js" --include="*.py"

# 4) 硬编码色值（:root 之外）
grep -RInE "#[0-9a-fA-F]{3,6}" frontend/assets --include="*.css"
```

## 5. 版本与命名

- 用户可见处不写"D0""骨架""草稿""MVP 演示"等阶段词；内部文档可保留版本号。
- 产品对外名称统一为"合规哨兵"；副标题统一为"内容合规体检（广告法 / 平台规则 / AI 标识）"。
- 提交信息用祈使句描述改动，不写"update""fix bug"。

## 6. 合规边界

- 产品定位：内容风险自查工具，不构成法律意见，不替代平台审核。
- 对外发布的 AIGC 宣传物料，由团队按《人工智能生成合成内容标识办法》评估是否需要显式标识；产品界面、代码、文档中不得出现制作过程痕迹。
